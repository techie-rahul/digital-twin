Algorithm A: Stateful DFS Search Inventory Engine

🎯 Judge Objection Playbook

Q: "Where do you get ServiceFlow data in real life?"

A: Existing CMDBs (ServiceNow), network application dependency maps (AWS Discovery, Dynatrace/Datadog), and Kubernetes service manifests. Our JSON schema is lightweight for instant ingestion.

Q: "Why not use an LLM or RL agent for the adversary?"

A: Change boards require mathematical determinism. If an LLM gives different answers at 9 AM and 10 AM, the CAB cannot legally approve it. Our seeded Monte Carlo engine is deterministic and reproducible down to the seed.

Q: "Isn't finding all paths too slow on massive graphs?"

A: That is why Algorithm A (bounded stateful DFS) and Algorithm B (Monte Carlo walks) are decoupled. Algorithm A runs once with depth 8 / 5,000 states caps. Simulation latency is under 40 milliseconds even on hospital and energy grid twins.

Q: "Why call 65% path reduction misleading?"

A: Path reduction assumes an attacker hits a closed door and gives up. In reality, attackers adapt. We prove that when jump hosts get MFA, the attacker pivots via Route D (CI/CD machine token) and still breaches the database.
